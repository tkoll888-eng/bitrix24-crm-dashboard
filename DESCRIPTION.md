# CRM-дашборд по сделкам — краткое описание

## Назначение и реализованные сценарии

Встраиваемое приложение-дашборд для Битрикс24, открывается внутри портала и
работает от лица авторизованного пользователя. Показывает аналитику по сделкам
CRM текущего портала через REST-прокси Вайбкода (запросы к порталу делает только
сервер, ключ в браузер не попадает).

Реализованные сценарии:

1. **Ключевые показатели (KPI):** общая сумма открытых сделок портала (± их
   количество), количество и сумма выигранных сделок за период, средний чек по
   выигранным за период.
2. **Сводка по стадиям воронки:** количество сделок и их сумма по каждой стадии
   (`stageId`) с визуальным распределением по объёму суммы; подписи стадий
   резолвятся из справочника статусов CRM.
3. **Последние сделки:** список последних (до 15) сделок с названием, суммой,
   стадией и ответственным; название сделки ведёт на карточку сделки в портале.
4. **Фильтр по периоду создания сделки:** пресеты (30/90/180 дней, год, всё
   время) и произвольный диапазон «с — по». Период применяется на сервере как
   фильтр `createdAt` ко всем запросам, включая агрегаты.

Воронка и показатели считаются **серверными агрегатами**
(`/deals/aggregate`), а не пересчётом одной страницы — это единственный честный
источник цифр. Сервер проверяет флаг `truncated` у агрегатов и честно
предупреждает, если период настолько широк, что портал обработал лишь часть
данных.

## Запрошенные скоупы и обоснование

Приложение только читает CRM, ничего не создаёт и не меняет.

- **`crm` (deals)** — чтение сделок (`/deals/search`, `/deals/aggregate`) для
  всех трёх блоков дашборда. Без него приложение бессмысленно.
- **`crm` (statuses)** — справочник стадий воронки (`/statuses/search`) для
  преобразования кодов `stageId` в человекочитаемые названия.
- **`user`** — справочник пользователей (`/users/search`) для вывода имени
  ответственного по сделке. **Опционально**: при его отсутствии приложение
  работает, но имя ответственного не показывается.

## Известные ограничения

- **Права пользователя:** видны только сделки, к которым у пользователя есть
  доступ в Битрикс24 (права применяются на стороне портала).
- **Без скоупа `user`** имена ответственных не резолвятся (показывается «—»);
  остальные блоки работают в полном объёме.
- **Широкие периоды:** агрегат по «всему времени» на крупном портале может
  досчитаться не полностью — сервер видит `truncated` и советует сузить период.
- **Мультивалюта:** суммы не конвертируются, показываются числовые значения сделок.
- **Ключ не хардкодится:** читается из `process.env`; в репозиторий/архив не
  попадает. Без ключа сервер стартует и показывает состояние «портал не
  подключён» вместо падения.

## Инструкция для проверяющего

1. Локально: `npm install` (зависимостей нет) и `npm start` — сервер поднимается
   на `process.env.PORT || 3000`.
2. Открыть `https://app-<id>.vibecode.bitrix24.tech` во встроенном браузере
   Коворка (там есть сессия портала) либо добавить приложение как пункт левого
   меню Битрикс24.
3. Проверить сценарии: вкладки **Обзор / Воронка / Сделки**; переключить
   **период** (пресет или диапазон) и нажать «Применить» — все блоки
   пересчитываются по новому периоду.
4. Если ключ портала не привязан — убедиться, что интерфейс показывает
   «портал не подключён», а не падает.
